### 1.2 Locking Primitives

```c
typedef struct {
    StaticSemaphore_t xMutexBuffer;
    SemaphoreHandle_t xMutex;
    StaticSemaphore_t xBinarySemBuffer;
    SemaphoreHandle_t xBinarySem;
    UBaseType_t uxHighWaterMark;
} Lock_t;

typedef struct {
    StaticSemaphore_t xRecursiveMutexBuffer;
    SemaphoreHandle_t xRecursiveMutex;
    TaskHandle_t xOwner;
    uint32_t ulLockCount;
} RecursiveLock_t;
```

**Locking Rules:**
1. No spinlocks -- always use FreeRTOS blocking mutexes with portMAX_DELAY.
2. Lock ordering: System > App > Manager > Driver. Violation causes deadlock detection.
3. All locks are statically allocated (StaticSemaphore_t) -- no heap in IRQ context.
4. Critical sections in ISRs use taskENTER_CRITICAL()/taskEXIT_CRITICAL() -- max 5 us.
5. Mutexes are never locked recursively unless declared as RecursiveLock_t.

## 2. Camera Manager

### 2.1 Purpose
Captures raw 640x480 RGB frames from the OV5640 camera sensor at 30 FPS, performs basic preprocessing (auto-exposure, white balance), and delivers frames to downstream consumers via dual-buffered FreeRTOS queues.

### 2.2 Responsibilities
- Initialize OV5640 sensor via CSI-2 interface
- Configure sensor parameters (resolution, FPS, gain, exposure)
- Stream frames continuously with less than 33 ms per frame
- Perform Auto-Exposure (AE) and Auto-White-Balance (AWB) tuning
- Detect sensor hang and trigger recovery reset
- Provide dual-buffering to decouple capture from processing

### 2.3 Inputs
- SystemConfig_t from Configuration Manager at init
- SystemCmdMsg from System Manager (start/stop/configure)
- OV5640 sensor hardware via CSI-2

### 2.4 Outputs
- RawFrameMsg to Depth Processing queue
- RawFrameMsg to Object Detection queue
- CameraStatusMsg to Diagnostics Manager every 1000 frames

### 2.10 State Machine

```
IDLE -----> INIT -----> CONFIG -----> STREAMING -----> ERROR
  ^            |            |              |  |            |
  |            v            v              |  |            |
  +----<--- DEINIT <--------+--------------+  v            |
                                              STOP ---> RECOVERY
                                                        |
                                                        v
                                                      REINIT
```

- IDLE: Power off, no clocks.
- INIT: GPIO, I2C, CSI-2 PHY, clocks enabled.
- CONFIG: Register writes (resolution, format, FPS, AE/AWB).
- STREAMING: Continuous frame capture.
- STOP: Sensor in standby, clocks gated.
- ERROR: On I2C NACK, DMA underrun, or consecutive timeout.
- RECOVERY: Toggles reset pin, waits 100 ms, re-initializes. Max 3 attempts then panic.

### 2.11 Thread Interaction

CameraTask (priority 5) runs on core 0 (reserved for I/O). ISR (VSYNC) wakes the task via xTaskNotifyFromISR(). No other task accesses OV5640 registers directly. Dual-buffer swap is atomic under xBufferSem.

### 2.12 Error Handling

| Error | Detection | Action |
|---|---|---|
| I2C NACK | ov5640_read/write returns error | 3 retries with 10 ms backoff; if persistent, transition to RECOVERY |
| DMA underrun | CSI-2 controller error flag | Drop current frame, increment ulDroppedFrames, continue |
| Frame timeout | Watchdog timer fires (50 ms) | camera_handle_timeout() to RECOVERY |
| Buffer starvation | All buffers in use when new frame arrives | Drop oldest frame, increment ulDroppedFrames |

### 2.13 Exceptions

No C++ exceptions. All errors returned as ErrorCode_t. Fatal hardware faults trigger configASSERT() with system reset after log flush.

| Event | Severity | Rate Limit |
|---|---|---|
| Stream started/stopped | INFO | once per transition |
| Frame dropped | WARNING | 1 per 100 drops |
| I2C error | ERROR | 1 per 10 errors |
| Sensor recovery | WARNING | once per recovery |
| Frame rate deviation | INFO | 1 per minute |
| Fatal hardware fault | CRITICAL | once |

### 2.19 Recovery Strategy

1. Sensor timeout (50 ms no VSYNC) to toggle reset pin, wait 100 ms, full re-init.
2. I2C comm failure to 3 retries with exponential backoff; then reset.
3. More than 3 consecutive recoveries to configASSERT() with panic dump.
4. All recovery attempts logged to g_camera.ulRecoveryCount.

## 3. Depth Processing

### 3.1 Purpose
Processes raw camera frames through a stereo-matching or monocular-depth CNN (Edge Impulse model) to generate a 640x480 depth map indicating distance per pixel. Used for obstacle avoidance, navigation, and hazard detection.

### 3.2 Responsibilities
- Convert RGB frame to grayscale for depth inference
- Run Edge Impulse EON model for monocular depth estimation
- Apply temporal filtering to smooth depth predictions
- Generate confidence mask for each depth pixel
- Downsample to 160x120 for downstream consumers
- Compute Region-of-Interest (ROI) minimum distances

### 3.3 Inputs
- RawFrameMsg from Camera Manager queue

### 3.4 Outputs
- DepthMapMsg to Object Detection queue

### 3.11 Thread Interaction

DepthTask (priority 4) blocks on xInputQueue. After receiving a frame, it runs inference (no preemption during inference due to priority ceiling with CameraTask). The xMapMutex protects depth map reads by depth_get_roi_min_dist() from other tasks.

### 3.12 Error Handling

| Error | Detection | Action |
|---|---|---|
| Inference timeout | xTaskGetTickCount() delta > 100 ms | Log, skip frame, return error |
| Model output NaN | isnan(depth_out) | Clamp to 0, set confidence=0 |

## 4. Edge Impulse Runtime

### 4.1 Purpose
Provides the bare-metal inference engine for all Edge Impulse EON-compiled models (monocular depth, object detection, scene understanding, voice commands). Manages model loading, memory arena, input/output tensor handling, and model switching.

### 4.2 Responsibilities
- Load .tflite / EON-compiled model from serial flash
- Manage 256 KB contiguous inference arena
- Run inference with configurable input tensor
- Return output tensor with latency guarantee
- Support model hot-swap (depth, object detection, voice)
- Provide CMSIS-NN / SIMD optimized backend selection

### 4.3 Inputs
- Model binary blob (from flash at known offset)
- Input tensor pointer (caller-provided buffer)
- Model ID enum

### 4.4 Outputs
- Output tensor pointer (results)
- Inference time measurement

## 7. Object Tracking

### 7.1 Purpose
Tracks detected objects across successive frames using a Kalman filter / SORT-based tracker. Assigns persistent IDs to objects, estimates velocity, and predicts future positions for proactive hazard detection and navigation.

### 7.2 Responsibilities
- Maintain persistent object tracks with unique IDs
- Associate new detections to existing tracks via IoU + feature matching
- Run Kalman filter prediction and update per tracked object
- Remove stale tracks (no update for N frames)
- Estimate velocity and trajectory for moving objects
- Provide tracked object list to Navigation Engine

### 7.3 Inputs

### 7.4 Outputs

## 14. Hazard Priority Manager

### 14.1 Purpose
Receives hazard detections from Scene Understanding, assigns severity scores, computes time-to-collision / time-to-impact, and delivers prioritized hazard events to the Decision Engine.

### 14.2 Responsibilities

- Deliver highest-priority hazard(s) to Decision Engine

## 16. Path Planner

## 17. Obstacle Avoidance

### 17.1 Purpose
Provides real-time collision avoidance by monitoring the planned path against current depth data and object tracking. Generates micro-adjustments to heading and speed to avoid imminent collisions.

### 17.2 Responsibilities
- Receive planned path from Path Planner

- Detect imminent collision (TTI < threshold)
- Generate avoidance vectors (left/right/stop)

### 17.4 Outputs

### 22.20 Fall Detection Algorithm (Pseudocode)

```
Input:  accel[3], gyro[3] at 100 Hz
Output: FallEvent_t

Constants:
  IMPACT_THRESHOLD_G  = 2.5
  FREEFALL_THRESHOLD_G = 0.5
  ORIENTATION_CHANGE_DEG = 45
  POST_FALL_IMMOBILITY_S = 10

State machine (per-sample):
  1. Compute accel_magnitude = sqrt(ax^2 + ay^2 + az^2) / G
  2. If accel_magnitude < FREEFALL_THRESHOLD_G:
       Start freefall timer
       Set state = FREEFALL
  3. If state == FREEFALL and accel_magnitude > IMPACT_THRESHOLD_G:
       Record impact_timestamp
       Compute orientation change from gyro integration
       If orientation_change > ORIENTATION_CHANGE_DEG:
         Set state = IMPACT
         Start immobility timer (10 s)
  4. If state == IMPACT:
       Compute accel variance over 1 s window
       If variance < IMMOBILITY_THRESHOLD:
         Confirm fall
         Set state = CONFIRMED
         Trigger emergency alert
       Else:
         Set state = FALSE_ALARM
         Clear timers
```

## 27. Watchdog Manager

### 27.1 Purpose
Manages hardware and software watchdog timers to detect and recover from system hangs, task stalls, and infinite loops. Provides multi-layer watchdog hierarchy for granular fault isolation.

### 27.2 Responsibilities
- Initialize hardware watchdog (IWDG) with timeout
- Manage software watchdog timers for each task
- Monitor task liveness via periodic kick
- Detect task stalls (task not kicking its watchdog)
- Trigger system reset or recovery on watchdog expiry
- Maintain watchdog kick statistics for diagnostics

### 27.3 Inputs
- Watchdog kick signals from all tasks
- System health from Diagnostics Manager

### 27.4 Outputs
- System reset signal (hardware)
- Recovery request to System Manager

### 27.11 Thread Interaction
