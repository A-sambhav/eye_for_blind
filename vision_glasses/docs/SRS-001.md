# System Requirements Specification (SRS)

**SRS ID:** SRS-001

**Product:** AI-Powered Smart Glasses for Visually Impaired Users and Alzheimer's Patients

**Author:** Principal Systems Engineer (Apple, Google, Bosch)

**Revision:** 0.1

**Date:** 2026-07-27

---

## 1. Introduction

This document defines the complete system requirements for an AI-powered smart glasses system designed to assist visually impaired users and Alzheimer's patients. The system leverages Edge Impulse as the AI inference framework and is built on the Arduino UNO Q SBC platform with an array of sensors and human interface peripherals.

---

## 2. Purpose

The purpose of this SRS is to establish a clear, unambiguous, and traceable set of requirements for the design, development, verification, and validation of the AI-powered smart glasses system. This document serves as the primary reference for all stakeholders including engineering, product management, quality assurance, and regulatory affairs.

---

## 3. Scope

This SRS covers all hardware and software components of the smart glasses system, including sensor integration, AI model deployment, user interaction modalities, connectivity, power management, and safety mechanisms. Out of scope: cloud backend infrastructure, mobile companion applications, and manufacturing tooling.

---

## 4. Product Perspective

The smart glasses system is a wearable assistive technology device that augments the user's remaining senses through real-time AI perception, spatial audio feedback, and haptic cues. The system operates as a standalone edge device with optional connectivity to external services for map updates and model retraining.

## 8. Functional Requirements

### 8.1 Perception & Sensing

**FR-001** — The system shall detect obstacles in the user's path at distances up to 5 m using the depth camera.

**FR-002** — The system shall classify at least 50 common object categories with a confidence threshold of ≥ 85%.

**FR-003** — The system shall read printed text (Arial ≥ 12 pt) from flat surfaces at distances of 0.1-1.0 m.

**FR-004** — The system shall detect and recognize up to 20 enrolled faces within 2 seconds of facing the subject.

**FR-005** — The system shall estimate the distance to detected objects with an accuracy of ±10 cm up to 3 m.

**FR-006** — The system shall detect static and dynamic obstacles separately and prioritize moving obstacles.

### 8.2 Navigation & Localization

**FR-007** — The system shall acquire GPS fix within 60 seconds of cold start and within 10 seconds of warm start.

**FR-008** — The system shall provide turn-by-turn audio directions with precision of ±5 m of actual turn point.

**FR-009** — The system shall fuse GPS and IMU data to maintain position estimates during GPS-denied intervals up to 30 seconds.

**FR-010** — The system shall allow the user to set up to 10 geo-fence zones with configurable radii of 50-500 m.

**FR-011** — The system shall announce the current cardinal heading and nearest intersection upon voice request.

### 8.3 User Interaction

**FR-012** — The system shall accept voice commands from a vocabulary of at least 30 English phrases.

**FR-013** — The system shall provide all information to the user via bone conduction audio output.

**FR-014** — The system shall support a single physical button for emergency/attention functions.

**FR-015** — The system shall confirm all voice commands with a brief acknowledgment tone before execution.

**FR-016** — The system shall allow the user to interrupt audio output with a "stop" voice command.

**FR-017** — The system shall provide haptic feedback for alerts: one pulse for warning, three pulses for critical alert.

### 8.4 Safety Alerts

**FR-018** — The system shall detect fall events using IMU acceleration thresholds (≥ 2.5 g impact) within 500 ms.

**FR-019** — Upon fall detection, the system shall emit an audible alert and, if within Bluetooth range, notify a paired emergency contact.

**FR-020** — The system shall detect downward stairs, curbs, and drop-offs at distances ≥ 1.5 m.

**FR-021** — The system shall generate an audio warning when the user approaches within 1 m of a geo-fence boundary.

### 8.5 System Management

**FR-022** — The system shall report battery level in 10% increments via voice on request.

**FR-023** — The system shall enter a low-power sleep mode after 5 minutes of inactivity.

**FR-024** — The system shall wake from sleep mode upon detecting motion via IMU or voice command.

**FR-025** — The system shall automatically shut down when battery voltage reaches the BMS-defined critical threshold.

**FR-026** — The system shall allow remote model update over WiFi or Bluetooth when connected.

## 9. Non-Functional Requirements

### 9.1 Usability

**NFR-001** — A first-time user shall be able to complete a basic navigation task (walk 50 m with obstacle avoidance) within 10 minutes of initial use with no external instruction.

**NFR-002** — Audio prompts shall use a calm, neutral voice at a speech rate of 150-180 words per minute.

**NFR-003** — The system shall provide three volume levels accessible via voice command.

### 9.2 Reliability

**NFR-004** — The system shall operate without unrecoverable error for a mean time between failures (MTBF) of ≥ 2000 operating hours.

**NFR-005** — The system shall gracefully handle sensor disconnection and notify the user of the degraded mode.

**NFR-006** — The system shall recover from software crashes within 10 seconds via automatic watchdog reset.

### 9.3 Maintainability

**NFR-007** — The system software shall support over-the-air (OTA) firmware updates without requiring physical access.

**NFR-008** — AI model updates shall be deployable without modifying the inference pipeline code.

**NFR-009** — All software components shall be modular and independently testable via defined API boundaries.

### 9.4 Regulatory Compliance

**NFR-010** — The system shall comply with FCC Part 15 for unintentional emissions.

**NFR-011** — The system shall comply with EU Medical Device Regulation (MDR) 2017/745 Class I requirements.

**NFR-012** — The system shall comply with ISO 13485 quality management system standards for medical devices.

## 11. Hardware Requirements

**HR-001** — The system shall use Arduino UNO Q SBC as the primary compute platform.

**HR-002** — The depth camera shall have a minimum resolution of 640 × 360 at 30 fps with an operating range of 0.2-8 m.

**HR-003** — The RGB camera (if used) shall have a minimum resolution of 640 × 480 at 30 fps.

**HR-004** — The GPS module shall support concurrent GNSS (GPS + GLONASS or Galileo) with position accuracy ≤ 2.5 m CEP.

**HR-005** — The 9-axis IMU shall include accelerometer (±16 g), gyroscope (±2000°/s), and magnetometer with onboard fusion.

**HR-006** — The bone conduction speaker shall produce clear speech output at 60-80 dB SPL with frequency response 300 Hz-8 kHz.

**HR-007** — The microphone shall have a sensitivity of at least -42 dBV/Pa with a SNR ≥ 64 dBA.

**HR-008** — The battery shall be Li-Ion with capacity ≥ 3000 mAh, supporting 1C charge and 2C discharge.

**HR-009** — The BMS shall provide over-voltage, under-voltage, over-current, short-circuit, and over-temperature protection.

**HR-010** — The WiFi module shall support 802.11 b/g/n at 2.4 GHz with a range ≥ 30 m line-of-sight.

**HR-011** — The Bluetooth module shall support BLE 5.0 with a range ≥ 10 m.

**HR-012** — The total system mass shall not exceed 80 g mounted in the glasses form factor.

**HR-013** — The system shall include a power LED (green) and status LED (RGB) visible to the user.

## 12. Software Requirements

**SR-001** — The AI inference engine shall use the Edge Impulse SDK for Arduino.

**SR-002** — The software shall implement a publish-subscribe architecture for sensor data distribution.

**SR-003** — The software shall include a watchdog timer with a 10-second timeout and automatic reboot.

**SR-004** — The voice command engine shall use keyword spotting with a wake word before processing full phrases.

**SR-005** — All audio output shall be pre-processed through an equalizer tuned for bone conduction transducer response.

**SR-006** — The GPS driver shall implement a Kalman filter for position smoothing.

**SR-007** — The IMU driver shall implement Madgwick or Mahony filter for orientation estimation.

**SR-008** — The software shall maintain an event log in non-volatile memory with a minimum capacity of 1000 events.

**SR-009** — The software shall support a diagnostic mode accessible by holding the physical button for 10 seconds during boot.

**SR-010** — All user-configurable parameters (volume, wake word, geo-fence zones) shall be persisted across power cycles.

## 13. Safety Requirements

**SFR-001** — The system shall not generate audio output exceeding 85 dB SPL at the user's ear.

**SFR-002** — The bone conduction transducer shall have a maximum output force limited to prevent discomfort or injury.

**SFR-003** — The BMS shall disconnect the battery if cell temperature exceeds 60°C.

**SFR-004** — The system shall use only low-voltage components (≤ 5 V) in contact with the user.

**SFR-005** — All exposed materials shall be hypoallergenic and comply with REACH and RoHS directives.

**SFR-006** — The device shall not generate sustained heat exceeding 43°C on surfaces in contact with skin.

**SFR-007** — The system shall pass IEC 62368-1 safety standard for audio/video and ICT equipment.

**SFR-008** — The device shall include a visible and tactile emergency stop mechanism that disables all outputs.

**SFR-009** — In the event of a system fault, the audio output shall default to a safe state (silent or low-volume alert tone).

**SFR-010** — The device shall not interfere with implanted medical devices (e.g., pacemakers) per ISO 14708-1.

---

## 14. Security Requirements

**SCR-001** — All wireless communication (WiFi, BLE) shall use AES-256 encryption.

**SCR-002** — Firmware updates shall be signed with an ECDSA P-256 signature and verified before installation.

**SCR-003** — The system shall not expose any open network ports or services when not in an active pairing session.

**SCR-004** — Bluetooth pairing shall require user confirmation via physical button press or voice confirmation.

**SCR-005** — All stored credentials (emergency contact info, geo-fence coordinates) shall be encrypted at rest using AES-128.

**SCR-006** — The system shall implement rate limiting on voice commands (max 10 commands per 30 seconds) to prevent voice replay attacks.

**SCR-007** — Debug and diagnostic interfaces (UART, JTAG) shall be disabled in production firmware.

---

## 15. Privacy Requirements

**PVR-001** — The system shall process all personally identifiable data (PII) exclusively on-device with no cloud transmission.

**PVR-002** — Face recognition embeddings shall be stored as irreversible hashes, not raw images.

**PVR-003** — GPS location history shall be stored in a circular buffer of max 1000 waypoints and automatically cleared every 7 days.

**PVR-004** — Audio recordings (voice commands) shall be deleted immediately after processing and never stored.

**PVR-005** — The system shall provide a voice-accessible privacy mode that disables cameras and GPS while retaining IMU fall detection.

**PVR-006** — The system shall comply with GDPR Articles 5, 13, 17, and 32 (data minimization, transparency, right to erasure, security).

**PVR-007** — A clear privacy notice shall be printed on the device packaging and accessible via voice command ("privacy notice").

---

## 16. Accessibility Requirements

**AR-001** — All setup and configuration shall be achievable without any visual feedback.

**AR-002** — The physical button shall have a distinct tactile texture and be locatable by touch alone.

**AR-003** — Audio prompts shall follow Web Content Accessibility Guidelines (WCAG) 2.1 AA for speech output.

**AR-004** — The system shall support English as the default language with a framework for adding additional languages.

**AR-005** — For Alzheimer's users, the system shall repeat critical navigation instructions up to three times if no progress toward the destination is detected.

**AR-006** — The system shall provide a "return home" voice command that initiates navigation to a pre-configured home location.

**AR-007** — The system shall include caregiver configuration mode (accessible via Bluetooth from a companion device) to set safe zones, emergency contacts, and reminder schedules.

**AR-008** — The system shall support configurable reminder messages (e.g., medication, meals, appointments) triggered by time or geo-location.
